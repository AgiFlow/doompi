# Blog Outline

Create a structure that makes the reader promise, argument, and evidence visible before prose is written.

## Build the outline

- State the audience, reader problem, thesis, and practical outcome in plain language.
- Choose one primary angle and remove sections that do not advance it.
- Arrange sections in a clear progression from context to evidence to application.
- For each section, list its purpose, key claim, supporting sources, and any example or counterpoint needed.
- Identify claims that remain unsupported and questions that require a decision.
- End with a relevant next step rather than a generic conclusion.

Do not expand the outline into a full draft. Preserve the requested voice, length, and format constraints.

When `WORKFLOW_RUN_DIR` is provided, write only to the declared outline artifact. Otherwise use the destination requested by the user.
