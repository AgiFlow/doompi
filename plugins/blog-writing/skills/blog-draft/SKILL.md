# Blog Draft

Write a review-ready draft, not a published post.

## Drafting rules

- Follow the approved thesis and outline. Surface any necessary structural change instead of silently changing the brief.
- Open with the reader's problem or stakes, then deliver the promised value without filler.
- Use specific examples, concrete language, varied sentence length, and informative headings.
- Link factual claims to the provided sources. Label interpretation as interpretation.
- Preserve uncertainty where the evidence is uncertain. Do not invent proof, quotes, results, or personal experience.
- Match the requested voice without imitating a living author.
- Never use em dash characters. Use commas, colons, periods, or parentheses instead.

Include only frontmatter fields requested by the user or workflow. Do not publish, update a CMS, or overwrite an existing post without explicit authorization.

When `WORKFLOW_RUN_DIR` is provided, write only to the declared draft artifact. Otherwise use the destination requested by the user.
